# AI 双栏论文阅读器项目计划书

> 本文依据同目录的 `项目要求.md` 制定，用于 AI 分阶段实施。需求文档是产品范围的依据；本计划的技术选型属于建议，阶段 0 验证后可调整。开发每阶段前先阅读两份文档，不把未实现的能力描述为已完成。

## 一、目标与边界

交付以原始英文 PDF 为视觉基准、以稳定结构化块为内容基础的双语阅读 Web 应用。主流程为导入论文、解析结构和公式、生成或关联中文译文、双栏阅读与同步、复制公式、生成笔记并跨论文检索。始终保留可独立阅读的原 PDF，结构化阅读器为默认中文模式，译文 PDF 为可选模式。

仓库现状：仅有示例 `main.py` 和需求文档，没有既有业务框架、测试或实际服务。先面向本地单用户实现，不在第一轮加入账号、协作或云端多租户。优先级用于分期，不删除原需求：

| 优先级 | 目标 | 完成条件 |
| --- | --- | --- |
| P0 可用闭环 | PDF 导入与解析、自动目录、原文 PDF + 中文结构化阅读、后端 AI 翻译、双向同步、可信公式的 LaTeX 复制、基础设置和任务状态 | 用户用真实论文从导入走到阅读、翻译、定位及复制；刷新不丢数据 |
| P1 产品完整性 | arXiv ID/URL、同路径译文 PDF 关联及译文 PDF 模式、完整同步模式与缩放、MathML/图片复制、笔记及语义检索 | 每项有自动化或可复现人工验收记录 |
| P2 精度增强 | 扫描件 OCR、复杂公式和版面、多栏/表格质量、公式解释推导、检索排序 | 基于质量样本持续优化，不伪装识别能力 |

## 二、架构与不可变约束

建议前端 React + TypeScript，使用 PDF.js 展示英文原 PDF、KaTeX 呈现译文公式；后端 Python FastAPI，SQLite 管元数据与任务，受控本地目录保存 PDF 和结构化产物，独立 Worker 处理解析与翻译。单机版优先采用数据库任务队列，出现实际吞吐需求再引入外部队列。解析、公式识别、翻译、检索向量化均封装为 Provider；前端只依赖稳定 REST API 和数据结构，不知道模型或解析器实现。Codex 主要生成论文笔记，不承担翻译，翻译由后端的 OpenAI 兼容 Provider 完成。

```text
Web UI -> REST API -> Paper / Settings / Search -> SQLite + managed files
                         |                            ^
                         v                            |
                    Task queue -> Worker -> Provider(s)
```

- Python 虚拟环境必须在仓库根目录 `Paperx/.venv` 创建。安装依赖、运行服务/Worker/测试都使用该环境；不得使用全局或其他项目的虚拟环境。前端依赖与锁文件置于本项目，生成数据和密钥加入忽略规则。
- 浏览器不能未经授权扫描上传文件原来的本地目录。“同路径自动查找译文 PDF”只能用于服务端管理目录或用户明确授权的目录；普通浏览器单文件上传时提供手动关联中文 PDF。自动匹配结果须供用户确认。
- arXiv ID 和 URL 先归一化，再仅从允许的 arXiv 来源下载 PDF；限制大小、超时和重定向，避免任意地址下载。上传检查文件格式与大小，服务端生成保存路径以阻止目录穿越。
- 用户在设置中输入兼容 OpenAI 格式的 API 地址、API Key；后端获取模型列表，用户可选择，未选择时使用列表第一个；空列表或连接失败明确报错。密钥不返回前端、不写日志；持久化需加密并妥善管理本机密钥，否则只保存于后端进程内并告知重启需重新填写。对可配置 API 地址进行 SSRF 校验，本地 Provider 若允许访问须明确标注为本地模式。
- 第三方翻译服务会接收论文内容：提交任务前说明数据外传和预计成本，任务支持错误可见、重试和取消；测试使用假 Provider，不依赖付费 API。

## 三、先确定的数据契约

`Paper` 保存 ID、来源、标题、原始 PDF、可选译文 PDF、解析版本与任务状态。`Document` 保存页尺寸/旋转、自动章节树、按阅读顺序排列的 `DocumentBlock`、译文映射和解析/翻译版本。`DocumentBlock` 至少支持 `heading`、`paragraph`、`formula`、`figure`、`table`、`citation`、`list`、`code`：

```json
{
  "id": "formula-001",
  "type": "formula",
  "page": 5,
  "order": 38,
  "bbox": { "x": 0.18, "y": 0.31, "width": 0.52, "height": 0.07 },
  "latex": "L=-\\log x",
  "number": "(3)",
  "confidence": 0.93
}
```

- 页码和坐标约定统一：页面从 1 编号，bbox 为相对于原 PDF 页面未旋转坐标系的归一化矩形；跨页/不连续块允许多个位置。前端按页面实际尺寸/旋转投影，不能把像素坐标固定写死。
- ID 在同一解析版本中稳定，不能由当前 DOM 序号临时产生。重解析须保留版本及旧新 ID 的映射，避免笔记、搜索、译文和阅读位置失效。译文块引用原文 `block_id`；拆分/合并时显式维护一对多关系。缺失映射要标记而不是猜测。
- 公式是第一类块，保存识别来源、LaTeX、编号、位置、置信度和人工修订版本。未知或低置信度公式不得提供看似正确的复制结果，应可查看/校正。公式与参考文献不翻译，专有名词采用术语表保护。
- 最小接口建议：`POST /papers`、`POST /papers/import-arxiv`、`GET /papers/{id}`、`GET /papers/{id}/document`、`GET /papers/{id}/pdf`、`POST /papers/{id}/translations`、`POST /papers/{id}/translated-pdf`、`GET /tasks/{id}`、`PUT /settings/ai`、`GET /settings/models`、`GET /search`。原 PDF 支持 Range 请求；具体响应与错误格式由阶段 0 的 OpenAPI/schema 和契约测试固化。
- 后台任务状态统一为 `queued/running/succeeded/failed/cancelled`，记录阶段、进度、错误和重试次数；上传/翻译幂等或可检测重复，失败不影响继续阅读原文，页面刷新可恢复任务状态。

## 四、实施阶段和验收门槛

各阶段交付代码、相应测试、可复现运行说明与已知限制。不得用纯静态演示替代真实调用；各阶段可拆成较小的独立任务，全部验收条件达成才标记完成。

### 阶段 0：工程基线与可行性验证

1. 建立项目内 `.venv`、前后端目录、锁定依赖、配置样例、忽略规则、测试脚手架和启动命令；现有 `main.py` 是示例，不当作业务功能。
2. 准备许可明确的测试 PDF：单栏、多栏、公式密集、图表、扫描页及中英成对文件；记录章节、页码、关键段落和公式的人工预期值。
3. 对候选 PDF 解析器与公式识别方案做小样本验证，确定数据 schema、坐标/旋转约定、API 错误格式、Provider 接口以及准确率限制。

**验收：**新环境只用项目 `.venv` 能启动后端、运行测试并启动前端；至少一篇样本导出包含稳定 ID、页码和坐标的结构；记录公式无法可靠识别时的人工校正降级策略。

### 阶段 1：导入、存储与解析

1. 实现拖拽/按钮上传、论文列表、最近打开、持久化原 PDF、导入进度与失败重试；支持 arXiv ID/URL 导入并避免重复。
2. 解析 PDF 的页、文本、章节、段落、阅读顺序及图表/公式候选区域；自动生成目录及各类块，保留版面坐标、来源和置信度。处理多栏顺序及文本层缺失，必要时允许按页降级。
3. 服务端管理目录中的译文 PDF 按确定规则匹配后供用户确认；普通文件上传可手动上传并关联译文 PDF。

**验收：**测试论文可重新打开原 PDF，自动目录能跳到正确章节；多栏样本按人工预期检查顺序；非法文件、下载失败和解析失败不会损坏论文记录，均可重试。

### 阶段 2：后端 AI 设置与结构化翻译

1. 提供设置 API 与界面：填写 API 地址和 API Key、拉取模型列表、选择模型；未选择时使用返回的第一个。无可用模型或认证失败时清晰报错，密钥不泄露。
2. Worker 按章节/块翻译并持续保存进度，保持章节结构、块映射、术语及公式、参考文献原貌；支持超时、取消、重试与失败块补翻。
3. 质量检查覆盖块缺失、顺序错乱、公式 LaTeX 被改写、参考文献被翻译等情况；保留原文与错误信息供复核。

**验收：**配置有效兼容服务后可完成真实论文翻译，译文块能追溯原文 `block_id`；断线/超时/无模型时不丢原文，可恢复任务；自动测试使用假 Provider 覆盖成功、空列表、失败和重试。

### 阶段 3：双栏阅读基础

1. 实现顶部工具栏、窄目录、尽可能宽的中央原文/译文双栏、窄右侧留白和底部状态栏。目录由文档结构生成，支持折叠与点击跳转。
2. 英文原文用 PDF.js 渲染，支持滚轮阅读、Ctrl+滚轮缩放、页码跳转与文本选择；中文默认结构化阅读器，按同一章节次序显示段落、图表、列表及 KaTeX 公式。无译文时提供翻译按钮、进度和失败提示。
3. PDF 页面覆盖层映射段落/公式位置，随缩放保持对齐；文本复制合并段内视觉换行、保留段落换行，跨行连字符区分排版断词与真实连字符。提供阅读位置恢复。

**验收：**桌面和窄窗口均可操作，无控件重叠；同一论文可在两侧读到对应内容；章节、页码、缩放、文本复制和刷新恢复在实际 PDF 上有效；无文字层时仍能读原始 PDF。

### 阶段 4：同步与公式 LaTeX 复制（P0 闭环）

1. 实现 OFF、PAGE、ANCHOR、SMART（默认）模式：OFF 独立；PAGE 对页；ANCHOR 依块映射对齐；SMART 优先可见锚点，并结合页面、可视区域与滚动方向，在缺映射时显式降级。禁止仅凭 `scrollTop` 比例同步。
2. 双向同步滚动和可关闭的同步缩放；区分用户滚动与程序定位，防止互相触发导致抖动。译文长度不同、页面跨越、无对应块时定位保持稳定。
3. 公式覆盖层提供点击/悬停操作并复制已校验的 LaTeX；译文公式复用原公式内容。低置信度结果需有校正操作及明确提示。

**验收：**在翻译长度明显不同的真实论文中，任一侧滚动都能稳定定位到另一侧相应块，OFF 完全独立，切模式和缩放不震荡；复制多个公式得到可渲染 LaTeX，不把乱码当成功。单元与浏览器测试覆盖缺失映射、防循环和复制。

### 阶段 5：译文 PDF、扩展公式能力

1. 在默认结构化模式之外支持已关联/生成的中文 PDF 模式，允许切换；有结构映射时按锚点同步，没有映射时只承诺页级近似同步，并在界面明确降级。中文 PDF 只是可选产物，不能代替结构化数据。
2. 增加 Copy MathML、Copy Image；Explain Formula 与 Derive Step by Step 通过后台 AI 请求实现，区分论文原文与 AI 推断，保持公式来源块可追溯。

**验收：**译文模式切换后阅读位置合理；三种复制结果可在对应目标中使用；无公式识别数据、无配置或 PDF 页码不一致时功能状态与提示准确。

### 阶段 6：论文笔记和跨论文语义搜索

1. 新建 `docs/AI/生成论文笔记.md`，提供供 Codex 使用的详细提示词：输入原 PDF/结构化块和论文元信息；输出研究问题、方法、公式解释、实验、结果、局限、术语和疑问；逐项引用页码及 `block_id`，区分事实、推断和未知。Codex 只负责笔记，不代替后端翻译。
2. 保存笔记及其版本，尽可能将笔记段落定位到原文；无法可靠定位的内容标记为“仅笔记”，不生成虚假锚点。解析版本变化时维护关联或重新生成。
3. 先建立跨论文关键词与块级跳转，再加入向量/混合检索以支持自然语言问题。Ctrl+K 打开搜索；显示论文名、命中摘录、来源、页码及跳转；笔记/文档变更时重建相关索引。

**验收：**多篇论文中查询“作者在哪里讨论 large batch size”等问题，结果能指向正确论文和具体段落；点击可跳转，空结果/索引未就绪有明确信息；使用人工标注的问题集评估召回和定位。

### 阶段 7：质量、回归与交付

1. 对单栏/多栏/扫描页、长论文、密集公式、异常 PDF、不同译文长度做端到端回归；测目录定位、覆盖层缩放、同步、任务重试、检索跳转与隐私边界，记录误识别和降级案例。
2. 补全启动、配置、备份/迁移、API Key 管理、Provider 替换、质量限制及故障排查文档；在新环境执行从上传到阅读和搜索的完整流程。

**验收：**单元、契约、集成和浏览器端到端测试通过；没有未说明的 P0 缺口，P1 未完成内容逐项列明；新的工作环境只使用项目内 `.venv` 可复现后端运行。

## 五、交给开发 AI 的执行规则

1. 每轮只实施一个阶段或明确可验收的子任务；先检查仓库现状和未提交改动，阅读相关代码与两份需求/计划文档，保护用户已有修改。
2. 开始前列出本轮输入、输出文件、依赖、风险和验收样本；阶段 0 的选型验证失败时，保留稳定 schema/API 并更新选型记录。
3. 先落实契约与关键测试，再做真实的端到端路径。可以用受控假 Provider 测试，但 UI 演示数据必须明确标识，不可宣称模拟调用已完成真实翻译。
4. 收尾执行项目内 `.venv` 的测试、前端构建与相关浏览器测试；报告实际命令和结果、尚未覆盖的外部服务测试、失败样例与下一阶段的前置条件。
5. 未满足本阶段验收标准时不推进状态，修正问题或如实记录阻塞；不得因“代码能编译”就标记产品能力完成。

## 六、主要风险和应对

| 风险 | 对策 |
| --- | --- |
| PDF 公式无法普遍精确反推 LaTeX | 阶段 0 做样本验证；保存置信度和来源；仅复制可信/人工校正结果，低质量识别列为 P2 |
| 多栏、表格或扫描件导致块顺序/位置错误 | 留存原 PDF、来源坐标和质量标记；按页降级，优先保证 PDF 阅读始终可用 |
| 中文 PDF 与原文版式/页码不同 | 缺结构映射时只提供标明为近似的 PAGE 同步，不能伪称 ANCHOR/SMART 精确定位 |
| 可配置 API 地址带来 SSRF、密钥泄露及成本风险 | 校验目标地址、安全保管 Key、后端限额/超时、日志脱敏、提交任务时说明数据外传 |
| 重解析破坏旧笔记/搜索锚点 | 文档、笔记、索引版本化并维护块 ID 映射，必要时重建索引 |
| 浏览器无法查找用户磁盘中的同路径译文 | 自动匹配仅用于授权/服务端管理的目录，其他情况提供手动关联 |

最终验收以 `PDF -> Structured Paper -> Bilingual Paper -> Interactive Paper -> AI-assisted Paper Understanding` 的实际可用链路为准。对无法准确识别、对齐和检索的情况诚实显示降级状态，绝不牺牲原文阅读能力。
