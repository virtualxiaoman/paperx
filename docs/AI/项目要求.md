# AI 双栏论文阅读器

## 1. 项目定位

本项目是一款面向科研人员、研究生以及需要大量阅读英文技术论文用户的 **AI 辅助论文阅读 Web 应用**。

项目的核心目标不是简单地将英文论文翻译成中文 PDF，而是建立一个：

> **以原始论文 PDF 为视觉基准，以结构化论文数据为内容基础，以 AI 为辅助工具的双语科研论文阅读器。**

用户可以在浏览器中打开一篇论文，同时查看：

* 最左侧：英文原始论文的大纲（Abstract、Introduction、Method、Experiments、Conclusion 等）
* 左侧：英文原始论文（滚轮滑动、Ctrl+滚轮缩放、支持页码跳转），需要支持公式的复制（可以直接复制出来正确的latex格式，可以使用markdown格式，比如复制出来是：`损失函数为$\mathcal{L}_q = - \log \frac{\exp(q \cdot k_+ / \tau)}{\sum_{i=0}^{K} \exp(q \cdot k_i / \tau)}$`）。
* 右侧：中文译文(结构与英文一致，不翻译参考文献、公式、专有名词)
* 左右两侧：全部同步，比如同步定位和同步缩放，该功能支持开启和关闭
* 底部/顶部：导航栏(未来可能开发新界面)、同步功能等阅读工具。

---

# 2. 核心用户需求

提高中英文阅读效率，希望这些操作集中在同一个阅读界面中完成。
普通 PDF 中的数学公式往往无法方便地复制成 LaTeX。 用户希望：

```text
看到公式
    ↓
点击公式
    ↓
Copy LaTeX
    ↓
得到：

L = -\sum_i y_i \log p_i
```

而不是复制成乱码或不可编辑字符。


# 3. 核心设计原则

## 3.1 PDF 与结构化文档分离

项目不能仅仅维护：

```text
original.pdf
translated.pdf
```

而必须同时其结构以方便展示、复制。

---

## 3.2 前端不依赖具体 AI 技术

前端不能知道：

* 使用什么 LLM
* 使用什么翻译模型
* 使用什么 PDF Parser
* 使用什么公式识别工具

前端只依赖统一的数据结构和 API。



## 3.3 AI 服务必须可以替换

项目需要采用 Provider 抽象。
未来更换 AI 模型时，不应修改核心业务逻辑。

# 5. 前端界面需求

## 5.1 主界面

整体采用三栏布局：

```text
┌─────────────────────────────────────────────────────────────┐
│                      顶部工具栏                             │
├──────────────┬──────────────────────────────┬───────────────┤
│              │                              │               │
│    论文目录   │         双语阅读区域          │ 本处暂时留白，为了对称美  │
│              │                              │               │
│ Abstract     │  English  │  Chinese         │         │
│ Introduction │  PDF     │  Reader          │       │
│ Method       │          │                  │       │
│ Experiments  │          │                  │             │
│ Ablation     │          │                  │               │
│ References   │          │                  │               │
│              │                              │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ 页码 │ 缩放 │ 同步状态 │ 阅读进度 │ 其他状态                 │
└─────────────────────────────────────────────────────────────┘
```

其中目录应该尽可能窄，右侧留白也应该尽可能窄，保证中间阅读区域尽可能宽。
目录应该是自动生成的，英文原文支持传入PDF或者arxiv id，中文译文支持自动检索本地相同路径下的PDF或者用户点击按钮请求后端AI进行翻译。

# 6. 左侧：论文目录

左侧负责显示论文结构。

例如：

```text
Abstract

1 Introduction

2 Related Work
  2.1 Contrastive Learning
  2.2 Instance Discrimination

3 Method
  3.1 Overview
  3.2 Momentum Encoder
  3.3 Queue

4 Experiments
  4.1 ImageNet
  4.2 Ablation Study

5 Conclusion
```

点击章节后：

```text
章节
 ↓
原文跳转
 ↓
译文同步跳转
```

目录应当由结构化文档生成，而不是手工写死。

# 8. 双栏同步需求

不能简单按照：

```text
scrollTop percentage
```

同步。

必须基于论文中的：

```text
block_id
```

进行同步。

例如：

```text
English:
p-001
p-002
formula-001
p-003

Chinese:
p-001
p-002
formula-001
p-003
```

当用户阅读：

```text
English → p-002
```

系统自动：

```text
Chinese → p-002
```

---

## 8.1 同步模式

系统支持：

### OFF

左右完全独立。

### PAGE

保持相同 PDF 页码。

### ANCHOR

按照段落、公式、Figure 等结构化 block 定位。

### SMART

综合：

* page
* block
* 当前可视区域
* 滚动速度

自动同步。

默认采用：

```text
SMART
```

# 9. 两种译文显示方式

项目同时支持两种翻译模式。

## 模式 A：Translated PDF

直接显示 AI 生成的中文 PDF。

优点：

* 最大程度保留论文排版
* 与原论文视觉对应

缺点：

* 文本、公式结构不容易操作
* 公式复制能力有限

---

## 模式 B：Structured Reader

将翻译结果作为 HTML/React 文档显示。

例如：

```text
Section
 ↓
Paragraph
 ↓
Formula
 ↓
Paragraph
 ↓
Figure
```

公式采用：

```text
LaTeX
 ↓
KaTeX
 ↓
Browser Rendering
```

这是默认推荐模式。

# 10. 论文内容结构

核心数据模型 `DocumentBlock`。

支持：

```text
heading
paragraph
formula
figure
table
citation
list
code
```

每一个 Block 必须有稳定 ID。

例如：

```json
{
  "id": "formula-001",
  "type": "formula",
  "page": 4
}
```

这样整个系统可以围绕：

```text
block_id
```

进行：

* 双栏同步
* 高亮
* 搜索
* AI 上下文
* 翻译
* 注释
* 跳转
* 公式复制

---

# 11. 公式系统

公式必须作为第一类对象。

例如：

```json
{
  "id": "formula-001",
  "type": "formula",
  "latex": "L=-\\log ...",
  "number": "(3)",
  "page": 5,
  "bbox": {
    "x": 120,
    "y": 300,
    "width": 500,
    "height": 80
  }
}
```

## 11.1 公式操作

鼠标移动到公式：

```text
┌──────────────────────────┐
│ Copy LaTeX               │
│ Copy MathML              │
│ Copy Image               │
│ Explain Formula          │
```

## 11.2 公式复制

必须支持：

```text
Copy LaTeX
```

得到：

```latex
L=-\log
\frac{\exp(q^T k_+/\tau)}
{\sum_i \exp(q^T k_i/\tau)}
```

同时支持：

```text
Copy MathML
Copy Image
```


# 12. AI Semantic Search

首先每篇文章都会使用codex生成一篇详细的阅读笔记，当阅读文章很多之后，需要支持自然语言搜索（Ctrl+K）：

```text
作者在哪里讨论 large batch size？
```

系统找到哪篇论文的什么位置，然后直接跳转到对应位置。


# 13. Codex、其他AI的职责

Codex 主要负责论文笔记的生成。不负责论文翻译（由后端的AI实现）
后端AI采用openAI格式，前端界面的设置中可以填入API请求地址和API Key，以及支持选择模型（通过API请求地址来获取模型列表，用户来选择模型，用户不选择则使用获取到的模型列表的第一个）。

# 14. 最终用户体验

理想操作流程应该是：

```text
① 拖入一篇英文论文 PDF或者点击上传或者传入arxiv id（支持url传递或者直接传入arxiv id）

                ↓

② 系统解析论文

                ↓

③ 阅读器展示如下

┌────────────┬───────────────────┬──────────────┐
│ 目录       │ English │ 中文     │ 留白部分           │
│            │                   │              │
│ Intro      │ 原文    │ 译文     │            │
│ Method     │                   │        │
│ Experiments│ 公式    │ 公式     │      │
└────────────┴───────────────────┴──────────────┘

                ↓

⑧ 遇到公式可以直接复制出 LaTeX 格式。注意PDF复制的时候遇到的段内换行应该自动去掉，段落之间的换行应该保留。

```

# 15. 项目的核心价值

这个项目最核心的并不是：

```text
PDF 翻译
```

而是建立一个：

```text
PDF
 ↓
Structured Paper
 ↓
Bilingual Paper
 ↓
Interactive Paper
 ↓
AI-assisted Paper Understanding
```

的完整链条。

另外还需要一份详细的提示词用来让codex生成详细的论文笔记，保存在`docs/AI/生成论文笔记.md`中。

最后，要求虚拟环境必须建立在PaperX文件夹下，不可以使用全局的虚拟环境或者其余项目的虚拟环境。
